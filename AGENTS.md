# Project rules
- Keep route scrolling in a single component inside BrowserRouter keyed by navigation entry: new pathname navigations reset instantly, repeat same-page navigations scroll smoothly, hash links (including initial loads and redirects) scroll smoothly to anchors with scroll margin for the navbar, and other POP navigation leaves native browser restoration untouched.
- Use the shared Tailwind display family for all titles and the global heading rule for normal weight and tracking, so typography changes never affect body text or controls.
- Keep all page media, brand asset and social profile link references in `src/content/media.ts` (the media map plus the `social` export), with future filenames beside fallback slots, so uploads and profile links need one update.
- Render brand wordmarks through `Wordmark` using the original asset SVG geometry and colours, with per-instance `useId` gradient identifiers to prevent navbar/footer collisions.
- Render Instagram through the shared `InstagramGlyph` with the official Simple Icons path sourced in the media map, filled in currentColor so every placement takes its band colour; the gradient variant stays available as a prop but is not used.
- Render Facebook through the shared `FacebookGlyph` with the official Simple Icons path sourced in the media map, in its monochrome currentColor variant so it reads the same as Instagram on both dark and cream bands.
- Render image/video slots through `SlotMedia` so absent videos show posters without broken playback.
- Photo slots in media.ts are `{ src, focus }` objects; focus is the object-position that keeps faces in the crop. Containers use aspect ratios matched to the photo orientation (aspect-[4/5] for portraits, aspect-[4/3] for cards), never fixed short heights.
- Keep home desktop imagery unchanged; the hero picture selects the centralised heroMobile slot below 768px and the heroWide slot from 1200px, with the hero slot serving tablet in between. From 1200px the hero is a split screen on the near-black field: the words panel (about 40% width, aligned to the navbar's left edge, cream and light gold, no scrims or text shadows) sits left and the wide photo fills the right side starting below the navbar height with object-position 0% 50% left-anchored, styled in the presentation sheet, so the desktop treatment stays independent of tablet and mobile. The mobile hero is a split layout (cover photo block with bottom fade, solid text panel below with its own CTA) styled in the presentation sheet so desktop and shared controls remain independent.
- MobileStickyCTA observes the home hero button exiting above the viewport, footer visibility and menu state, using the shared EarlyAccessButton and a separately tested visibility rule so the sticky CTA never duplicates a visible hero action.
- Home feature navigation uses native scrolling and scroll-snap with mobile-only indicators, keeping the existing desktop grid unchanged.
- Use `EarlyAccessButton` for the shared marketing action so its destination stays consistent.
- Preserve early access validation, email verification and registration behaviour during copy-only changes.
- Keep legal document text unchanged during marketing rewrites because those pages contain supplied legal documents.
- Keep the Light and shadow visual treatment in `src/styles/light-and-shadow.css`, activated by Layout and presentation-only hooks; content, media mappings and form logic stay independent so the design can be reverted separately.
- Scope home mobile layout to ls-home and mobile typography sizes to the shared below-768px rules; supporting text uses the sans family and headings/brand taglines use display, with only these two font families loaded to prevent unintended reading-font overrides.
- The compact navbar, full-screen menu and sticky CTA apply below the Tailwind `nav` screen (1200px), so tablet widths never wrap the inline desktop links.
